# git config

Единственный источник настроек git — скрипт [`gitconfig.sh`](./gitconfig.sh).
Сам `~/.gitconfig` в репозиторий **не коммитится**: он производный и генерируется
скриптом. Личность и секреты лежат в `~/.env` и тоже **не в git**.

## Философия

- Скрипт идемпотентен: можно запускать сколько угодно раз, результат один и тот же.
- Общие настройки (mergetool, `zdiff3`, `rerere`) живут в скрипте и приезжают
  на любую машину через `git pull` + перезапуск.
- Персональное (`user.name`, `user.email`, `github.user`) подтягивается из `~/.env`.
  Если `~/.env` нет — эти ключи просто не ставятся, и git вежливо попросит задать
  identity при первом коммите. Это нормально: форсирует настройку и не оставляет
  фейка вроде `owner@example.com` в истории.

## Что где лежит

| Путь                  | В git?    | Роль |
|-----------------------|-----------|------|
| `git/gitconfig.sh`    | ✅        | единственный источник настроек |
| `git/README.md`       | ✅        | этот документ |
| `~/.gitconfig`        | ❌        | генерируется скриптом, не трогаем руками |
| `~/.env`              | ❌        | личность/секреты, права `600` |

## Формат `~/.env`

Скрипт читает три переменные.
Пример:
```bash
GIT_AUTHOR_NAME="Иван Петров"
GIT_AUTHOR_EMAIL="12345+ivan@users.noreply.github.com"
GITHUB_USER="ivan"
```
Можно и с export — скрипт использует set -a перед source, так что обе формы работают.
Про email: бери noreply вида ID+username@users.noreply.github.com (ID виден в
GitHub → Settings → Emails). Коммиты всё равно привязываются к аккаунту, но реальный
почтовый адрес не светится в истории.

## Применение скрипта
```bash
cd ~/dotfiles/git
chmod +x gitconfig.sh
./gitconfig.sh
```
Скрипт сам подтянет ~/.env (если есть), проставит общие настройки, а из env —
user.name / user.email / github.user. Ошибется и выйдет с понятным сообщением,
если обязательной переменной нет (защита от «тихо записать пустоту»).

## Проверка результата
```bash
git config --global --list
git config --list --show-origin | grep -E 'user\.|github\.|merge\.|mergetool\.|rerere\.|alias\.'
```
Во второй команде смотри колонку file: — все значения должны приходить из
~/.gitconfig (а не из /etc/gitconfig или репозиторного .git/config).

## Как добавлять / менять настройки
Правь только git/gitconfig.sh, не ~/.gitconfig. 
Паттерн простой:
функция gc()- это обёртка над git config --global:
```bash
# новая группа настроек
gc <section>.<key> <value>
```
## Как удалять настройки (важно)
Скрипт не удаляет ключи, которых в нём больше нет — он только пишет. Если ты
убрал строку из скрипта, а в ~/.gitconfig настройка осталась (или ты когда-то правил
файл руками), она продолжит действовать. Два способа почистить:
Точечно — убрать конкретный ключ:
```bash
git config --global --unset <section>.<key>
# например:
git config --global --unset alias.old
```
Чистая переустановка — если накопилось мусора и хочешь, чтобы ~/.gitconfig
соответствовал скрипту один-в-один:
```bash
rm ~/.gitconfig
./git/gitconfig.sh
```
Это безопасно ровно в этой схеме.
Если держишь что-то только в файле — сначала перенеси это в скрипт, потом удаляй файл.

> [!IMPORTANT]
> Не редактируй `~/.gitconfig` руками. Хочешь настройку — добавь в скрипт.
> Иначе `~/.gitconfig` и скрипт разъедутся, и «единственный источник»
> превратится в два conflicting источника.

## Развёртывание на новой машине
```bash
sudo apt update && sudo apt install -y git

# 1. клонируем репо
git clone git@github.com:xxxyyy-97/dotfiles.git ~/dotfiles

# 2. заводим ~/.env с личностью (права 600)
umask 077
cat > ~/.env << 'EOF'
GIT_AUTHOR_NAME="Иван Петров"
GIT_AUTHOR_EMAIL="12345+ivan@users.noreply.github.com"
GITHUB_USER="ivan"
EOF

# 3. применяем git-настройки
cd ~/dotfiles
./git/gitconfig.sh
```

## Безопасность
~/.env содержит личность и, возможно, токены → права 600, в git никогда.
В gitconfig.sh не хардкодь user.name / user.email / github.user — даже в
private-репо. Репозиторий однажды станет public, или его форкнут, или ты скинешь
кому-то архив. Личное — только из env.
Общие вещи (mergetool, алиасы, zdiff3) — смело в скрипт, они не секрет.

## Шпаргалка
| Задача                        | Команда |
|-------------------------------|---------|
| Применить/обновить настройки  | ./git/gitconfig.sh |
| Посмотреть всё                | git config --global --list |
| Посмотреть откуда значение    | git config --list --show-origin |
| Убрать один ключ              | git config --global --unset <sec>.<key>|
| Полный reset по скрипту       | rm ~/.gitconfig && ./git/gitconfig.sh |
| Обновить на машине            | cd ~/dotfiles && git pull && ./git/gitconfig.sh |
