# vim — минимальный серверный конфиг
Один каталог, ноль плагинов, только встроенное. Цель — одинаковый Vim на рабочей машине, в WSL и на слабых серверах, где из редакторов есть только системный vim.
Конфиг деградирует постепенно: на Vim 9 с Nerd Font и truecolor выглядит как nvim-сетап, на Vim 7.4 по ssh — как аккуратный «серверный» vim без ошибок старта.

## Раскладка

```text
vim/.vim/
├── vimrc                   точка входа (~/.vim/vimrc, без точки в имени — так умеет Vim)
├── scheme.vim              выбор темы + флаги g:have_nerd_font, g:statusline_vcs
├── statusline.vim          статуслайн + winbar, цвета режимов, git-кэш
├── mappings.vim            все маппинги (leader = <Space>)
├── clipboard.vim           провайдеры буфера обмена (аналог nvim g:clipboard)
├── colors/tokyonight.vim   собственная тема (night/storm, truecolor + 256)
└── README.md
```
~/.vim — симлинк на этот каталог (stow). Машинное состояние в репозиторий не попадает: undo и история netrw живут в ~/.cache/vim/.

## Установка
```bash
stow -t ~ vim                      # или: ln -s ~/dotfiles/vim/.vim ~/.vim
[ -e ~/.vimrc ] && mv ~/.vimrc ~/.vimrc.bak   # ВАЖНО: ~/.vimrc побеждает ~/.vim/vimrc
```

## Буфер обмена
В Vim нет `g:clipboard` и часто нет `+clipboard` на серверах, поэтому провайдеры реализованы вручную:
- копирование — автокоманда `TextYankPost`,
- вставка — маппинги, читающие буфер в регистр `c`.

### Цепочка определения провайдера (порядок важен)

| окружение                             | copy                      | paste |
|---------------------------------------|---------------------------|-------|
| WSL + `win32yank.exe`                 | `win32yank.exe -i --crlf` | `win32yank.exe -o --lf` |
| WSL без win32yank                     | `clip.exe`                | `powershell.exe … Get-Clipboard` |
| SSH (`$SSH_TTY` / `$SSH_CONNECTION`)  | OSC 52 в `/dev/tty`       | `<leader>p` вставляет внутренний регистр (как `osc52_paste=false` в nvim) |
| macOS                                 | `pbcopy`                  | `pbpaste` |
| Wayland + wl-clipboard                | `wl-copy`                 | `wl-paste --no-newline` |
| X11 с `+clipboard`                    | нативно: `clipboard=unnamedplus`, работает просто p | нативно |
| X11 без `+clipboard`                  | `xclip` / `xsel`          | то же |

### Как пользоваться
| действие                          | клавиши |
|-----------------------------------|---------|
| обычный yank → в системный буфер  | `yy`, `yw`, `yap`… (автокоманда `TextYankPost`, только безымянный регистр) |
| вставить из системного буфера     | `<leader>p` / `<leader>P`, в visual — `<leader>p` |
| скопировать не трогая `"`         | `<leader>y{motion}`, `<leader>yy` (текст дублируется в регистр `c`: `"cp`, `<C-r>c`) |
| скопировать диапазон / весь файл  | `:ClipCopy`, `:'<,'>ClipCopy` |
| перечитать буфер в регистр `c`    | `:ClipLoad` |
| диагностика                       | `:ClipInfo` |

### Нюансы
- OSC 52 пишет, но не читает: почти все терминалы (включая Windows Terminal) запрещают чтение буфера, поэтому по ssh вставка — средствами терминала (`Ctrl+Shift+V`).
Vim 8+ понимает bracketed paste, `set paste` не нужен.
- В tmux для OSC 52 нужно `set -g set-clipboard on` и `set -g allow-passthrough on` (tmux ≥ 3.3).
- У OSC 52 есть потолок размера payload — очень большие блоки могут не долететь; для логов надёжнее `:ClipCopy` локально или `scp`.
- Копирование асинхронное (`job_start`), когда доступно: `win32yank.exe` из WSL отвечает ~50–100 мс, блокировать ими каждый yank нельзя.
- `<leader>y` сохраняет и восстанавливает безымянный регистр: по `:help quotequote` любой янк, даже `"cy`, пишет и в `"`.
- На машине с нативным X11 и `+clipboard` весь этот слой отключается (`finish`): там честный `unnamedplus`, и `p` работает как обычно.

## Statusline и winbar
`statusline.vim` собирает строку-шаблон (`%#Group#`, `%{Func()}`, `%=`) и кладёт её в опцию; Vim исполняет её сам при перерисовке. 
Функции в `%{…}` глобальные (`StMode`, `StName`, `StBranch`…), потому что `s:` в этом контексте не виден.

*Две ветки*, выбор один раз при загрузке (`exists('+winbar')`):
- Vim с winbar → имя файла в шапке каждого окна + один глобальный статуслайн (laststatus=3);
- Vim без winbar (например, 9.1 ранних патчей) → имя файла в статуслайне каждого окна (laststatus=2), активное/неактивное через WinEnter/WinLeave. Это же экономит строку: 1 на окно вместо 1+1.

*Цвет блока режима* берётся из групп темы и меняется через `ModeChanged`:
| режим             | донор цвета   | в tokyonight  |
|-------------------|---------------|---------------|
| NORMAL            | Function      | синий         |
| INSERT            | String        | зелёный       |
| VISUAL / V-BLOCK  | Statement     | фиолетовый    |
| REPLACE           | Error         | красный       |
| COMMAND           | WarningMsg    | жёлтый        |
| TERMINAL          | Special       | бирюзовый     |

*Git* (`g:statusline_vcs=1`): branch и `+N -M` по текущему файлу.
Вызов `git` — только на `BufEnter`/`BufWritePost`/`FocusGained`, результат кэшируется в `b:vcs_*`;
при перерисовке статуслайн читает переменные, а не процесс. При `+job` — асинхронно.

*Вместо LSP-диагностики* (в Vim её нет) — счётчик quickfix (`QF n`).

Все цвета выводятся из групп темы через `synIDtrans()` и пересоздаются на `ColorScheme`,
поэтому тема и статуслайн не рассинхронизируются. Символы заданы кодами (`nr2char`),
а не литералами — не теряются при копировании и не зависят от кодировки файла; при не-utf-8 локали включается ASCII-фолбэк.

## Тема
`colors/tokyonight.vim` — рукописное приближение палитры `folke/tokyonight.nvim` (раскраска по классическим syntax-группам). 
Задаёт `gui*`, и `cterm*`, поэтому переключение `termguicolors` не требует перезагрузки темы. 
Включает ANSI-цвета для `:terminal` (`g:terminal_ansi_colors`) и группы netrw.

Если файл темы не доехал до сервера, `scheme.vim` молча откатывается на `slate`.

## netrw
Настройки: `alto=1`, `altv=1` (сплиты снизу/справа), `winsize=75`, `preview=1`.
Свои клавиши вешаются на `FileType`.
| клавиша       | действие |
|---------------|----------|
| u, <CR>       | открыть файл/каталог (как open в neo-tree; штатная u — история каталогов — уехала) |
| P             | превью |
| o / v / t     | открыть в hsplit / vsplit / новом табе |
| p             | превью-окно |
| q             | закрыть панель |
| R             | перечитать листинг |
| <C-h/j/k/l>   | навигация по окнам (перебивает netrw-овский <C-l>-refresh) |
| -, gh, i      | вверх, дотфайлы, стиль списка |
Известная болячка: tree-режим (`liststyle=3`) ломается на симлинках (склеивает путь вида `file/file`). Лечится `liststyle=0/1` или `keepdir=0`.

## Маппинги (шпаргалка)
leader — `<Space>`. Группы:
1. буферы:
- `bl/bh` next/prev,
- `bd` удалить альтернативный,
- `bx` удалить принудительно,
- `bc` закрыть текущий сохранив окно,
- `bb/bs/bt` пикер (`:ls + :b/:sb/:tab sb`)
2. табы: `tn/tx/tl/th/to/tm`, `<leader>1..4`
3. окна:
- `sv/sg` сплиты,
- `sx/so` закрыть/только это,
- `sw/sW` назначить/сбросить окно-приёмник для netrw (`g:netrw_chgwin`), `<C-h/j/k/l>`
4. терминал (только при `+terminal`):
- `tt` таб,
- `sT` снизу,
- `st` справа,
- выход из job-режима - `jj` или `<Esc>` (`<C-w>N`)
5. файлы:
- `<leader>e` netrw,
- `<leader>f` `:find` (работает `path+=**`),
- `<leader>w/q` write/quit,
- `w!!` сохранить через sudo
6. прочее:
- `<leader>h` nohlsearch,
- `<leader>c` list,
- `<leader>n` relativenumber,
- `F2` paste,
- `Y` = `y$`

## Серверная гигиена
- `lazyredraw`, `ttimeoutlen=10` (Esc не залипает по ssh), `synmaxcol` против километровых строк;
- `complete-=i` — автодополнение не сканирует include-файлы;
- persistent undo — в `~/.cache/vim/undo`, swap/backup-мусор в репозиторий не коммитится (`.gitignore`);
- большие файлы (>2 МБ) открываются в щадящем режиме (`undolevels=-1`, урезанный `synmaxcol`);
- состояние вне репо: `~/.cache/vim/{undo}`, `.netrwhist` через `g:netrw_home`.

## Совместимость
| фича                                                      | минимум |
|-----------------------------------------------------------|---------|
| `TextYankPost`, `job_start`, `:terminal`                  | Vim 8.0 |
| `laststatus=3`, `%{%…%}`-подобные трюки не используются   | Vim 8.2+ |
| `winbar`                                                  | поздние 9.1.x (проверяется `exists('+winbar')`) |
| всё остальное                                             | Vim 7.4 (без автокопирования и терминала) |
Проверка сборки: `vim --version | grep -o '+terminal\|+clipboard\|+job'`.

## Диагностика
```vim
:messages                     " ошибки старта
:scriptnames                  " какие файлы подключились
:verbose set statusline?      " кто и на какой строке поставил опцию
:ClipInfo                     " активный clipboard-провайдер
:echo exists('+winbar')       " 0 → работает fallback с per-window статуслайном
:echo &undodir                " должно быть ~/.cache/vim/undo
```
Шрифт терминала (глифы): `printf '\ue0b0 \ue0b2 \u25cf \u258e\n'` — квадратики в первых двух = нет Nerd Font,
ставь `g:have_nerd_font=0` или меняй шрифт.

## Что сознательно не сделано
- LSP/диагностика — нет; заменено quickfix-счётчиком и `:grep`/`:find`.
- Fuzzy-файндер — нет; `:find` с `path+=**` + wildmenu, `:b` с Tab.
- Плагины — нет ни одного; всё, что выше, собрано на встроенном, чтобы конфиг жил на машине, где нет ни сети, ни root, ни места.
